# 재시작설정 — 모든 워크스페이스의 자동 재개 규칙 (단일 원본 · 맥/윈도우 공용)

**규칙은 이 폴더에만 있다.** 각 워크스페이스 폴더에 심는 것은 딱 두 가지 —
`.vscode/tasks.json`(폴더를 열면 여기로 되돌아오는 발판)과 `CLAUDE.md` 의 관리 블록이다.
폴더마다 규칙을 두지 않는다. **새 폴더를 만들면 다음 재개 때 둘 다 자동으로 심긴다.**

## 언제 무엇이 도나

| 상황 | 맥 | 윈도우 | 하는 일 |
|---|---|---|---|
| PC 켜짐·로그인 | launchd `kr.claudecode.resume` | 작업 스케줄러 `ClaudeCode-자동재개` | `resume_all` |
| 인터넷 끊김 → 복구 | launchd `kr.claudecode.netwatch` | 작업 스케줄러 `ClaudeCode-회선감시` | 30초 이상 끊겼다 돌아오면 `resume_all` |
| 사람이 재시작 | 루트의 `재시작.command` | 루트의 `재시작.cmd` | 편집기 정상 종료 → `resume_all` |
| 편집기로 폴더를 열 때 | 그 폴더 `.vscode/tasks.json` | 같음 | `resume_claude <폴더>` — **항상** 이어받는다 |

`resume_all` 의 순서: `sync`(새 폴더에 발판) → 회선 대기 → (설정했다면) 서비스 깨움 →
**claude 가 죽어 있는 폴더만** 표식을 남기고 편집기로 연다(간격을 둔다) → 정해진 시간 안에
안 뜨면 터미널/새 창으로 직접 띄운다.

## 파일

```
설정.txt           ★ 손댈 곳은 여기뿐 — 폴더 위치·제외 폴더·시간값 (맥·윈도우 공용)
README.md          이 문서

lib.sh             (맥) 공용 함수
sync.sh            (맥) 발판·규칙 심기 — resume_all 이 매번 먼저 부른다
resume_claude.sh   (맥) claude 를 띄우는 유일한 곳
resume_all.sh      (맥) 전체 재개
netwatch.sh        (맥) 회선 감시
재시작.command      (맥) 손으로 전체 재시작

win/common.ps1        (윈도우) 공용 함수
win/sync.ps1          (윈도우) 발판·규칙 심기
win/resume-claude.ps1 (윈도우) claude 를 띄우는 유일한 곳
win/resume-all.ps1    (윈도우) 전체 재개
win/netwatch.ps1      (윈도우) 회선 감시
win/재시작.cmd        (윈도우) 손으로 전체 재시작 (restart.cmd 도 같은 것)
win/restart.ps1       (윈도우) 위 파일이 부르는 알맹이

프롬프트/_기본.txt      재개 때 claude 에 주는 첫 지시 (폴더별로 <폴더이름>.txt 를 두면 그게 우선)
상태/                  로그·pid·표식·선택 설정
  재시작로그.jsonl      언제 왜 무엇을 했나
  회선로그.jsonl        끊김·복구 기록
  고정세션.txt          (선택) 폴더이름 대화ID — 대화를 못박는다
  서비스.txt            (선택) 폴더이름 자동실행이름 — 재개할 때 함께 깨운다
  <폴더>.끔             그 폴더만 끈다
  .전체끔               전부 끈다
```

## 워크스페이스 판별 (새 폴더 자동 적용)

`설정.txt` 의 `루트` **바로 아래 폴더 = 워크스페이스**.
`제외` 에 적은 이름과 숨김 폴더(`.`으로 시작)는 뺀다.
`컨테이너` 에 적은 폴더는 자기 자신이 아니라 **그 안의 하위 폴더**가 워크스페이스다.
`재시작설정` 자신도 워크스페이스다 — 이 폴더의 claude 도 함께 이어받는다.

## 이어받을 대화를 고르는 법

`claude --continue` 는 **가장 최근에 손댄** 대화를 문다. 잠깐 띄운 빈 대화가 진짜 작업 대화를
가리는 사고가 있었다. 그래서 `설정.txt` 의 `최소대화크기` 이상인 대화 중 그 폴더의 것을 골라
`--resume <ID>` 로 집는다.

**★ 대화 폴더는 경로 글자 수만 같으면 겹친다.** claude 는 대화를
`~/.claude/projects/<경로의 비영숫자를 전부 '-' 로 바꾼 이름>` 에 넣는다. 그래서 이름 길이가 같은
두 폴더는 **한 폴더를 나눠 쓴다.** 시각만 보고 고르면 남의 폴더 대화를 문다(실제로 겪었다).
그래서 **대화 파일 안의 `cwd` 를 워크스페이스와 대조해서** 고른다. 못 고르면 `--continue` 가 아니라
**새 대화**로 간다 — `--continue` 는 이 상황에서 위험하다. `sync` 는 겹치는 폴더 쌍을 매번 `[!]` 로 알린다.
확실히 못박고 싶으면 `상태/고정세션.txt` 에 `폴더이름 대화ID` 를 적는다.

## 살아있음 판정

시각이 아니라 **프로세스**를 본다. 시각만 보다가 창을 두 번 띄운 적이 있다.
- 맥: `상태/<폴더>.pid` 의 PID → 아니면 cwd 가 그 폴더인 claude 프로세스(경로 문자열이 아니라 inode 비교).
  `pgrep -x claude` 는 편집기 터미널의 claude 를 놓치므로 `ps` 의 comm 으로 고른다.
- 윈도우: `상태\<폴더>.pid` 의 프로세스 → 아니면 명령줄에 그 폴더의 대화ID 가 들어 있는 claude 프로세스.

## 한글 폴더이름 주의 (맥)

맥 파일이름에는 NFD(자모 분리)로 저장된 것이 섞여 있어, 셸이 주는 폴더 이름이 폴더마다 다르다.
정규화하지 않으면 대화 폴더 이름이 어긋나 **조용히 새 대화로 떨어진다.** `cd`+`pwd` 로는 정규화되지
않는다 — 셸은 준 글자를 그대로 돌려준다. 그래서 `lib.sh` 의 `norm_path` 가 python 으로 NFC 로 맞추고,
워크스페이스 목록은 모두 이 함수를 거친다. 윈도우도 `win/common.ps1` 에서 같은 일을 한다.

## 끄기

- 한 폴더만: `상태/<폴더이름>.끔` 파일을 만든다
- 전부: `상태/.전체끔` 파일을 만든다
- 자동실행 자체를 내리기: 설치 꾸러미의 `제거.command`(맥) / `제거.bat`(윈도우)

## 두 대 이상의 PC 에서 같은 폴더를 쓸 때

발판(`tasks.json`)에는 그 PC 의 절대경로가 들어간다. 클라우드 동기화로 **같은 작업 폴더를
맥과 윈도우가 함께** 쓰면 두 PC 가 서로 발판을 고쳐 쓴다(작동은 하지만 파일이 계속 바뀐다).
그럴 땐 한쪽 PC 에서 그 폴더를 `설정.txt` 의 `제외` 에 넣거나, 동기화에서 `.vscode` 를 빼는 것이 낫다.
`CLAUDE.md` 관리 블록에는 절대경로가 없어서 PC 가 달라도 그대로 쓴다.

## 윈도우에서의 글자 문제 (알아 둘 것)

- **`.ps1` 파일은 UTF-8 BOM 으로 저장돼 있다.** 윈도우 PowerShell 5.1 은 BOM 이 없으면 한글을
  ANSI 로 잘못 읽어, 설정 이름(`루트`·`제외`)과 폴더 이름(`상태`·`프롬프트`)이 깨진다.
  이 파일들을 고칠 때는 **UTF-8 (BOM 포함)** 으로 저장해야 한다. (메모장은 'UTF-8 BOM', VS Code 는
  오른쪽 아래 인코딩 → 'UTF-8 with BOM 으로 저장')
- **`.cmd`·`.bat` 파일에는 한글을 넣지 않았다.** 배치 파일은 콘솔 코드페이지로 읽히기 때문에
  한글이 들어가면 PC 설정에 따라 깨진다. 그래서 이 파일들의 **내용은 순수 영문**이고,
  파일 이름만 한글이다(`설치.bat` = `install.bat`, `재시작.cmd` = `restart.cmd` — 내용이 같다).
- 루트에 만들어지는 `재시작.cmd` 는 그 PC 의 코드페이지(OEM)로 쓴다. 혹시 글자가 깨져 안 되면
  `재시작설정\win\재시작.cmd` 를 직접 쓰면 된다 (그 파일은 순수 영문이라 언제나 된다).

## 안전

되살아난 claude 에게 주는 첫 지시(`프롬프트/`)는 **읽고 점검해서 보고**로 끝난다.
사람이 없는 사이에 파일을 고치거나 발행·전송·배포하지 않는다. 폴더마다 지시를 바꿀 수 있지만,
이 원칙은 지키는 편이 좋다.
